2026-06-04 template-aligned SFT preprocessing rewrite plan

Reason for rewrite
- The current `src/sft_binidx.py` still hardcodes a Python-side copy of the chat template.
- The user has updated the chat template behavior and provided new golden references in `data/SFT/sample/my_sample.jsonl`, `data/SFT/sample/my_sample_outs.txt`, and `data/SFT/sample/final_pattern.txt`.
- The old Python replica is now divergent enough that patching it further is riskier than rewriting the SFT preprocessing around real Jinja rendering.

Target behavior to match exactly
- Rendering `data/SFT/sample/my_sample.jsonl` with the latest intended chat template must reproduce `data/SFT/sample/my_sample_outs.txt`.
- A single serialized sample must end as:
- `...<|im_end|>\n<|endoftext|>`
- When packing multiple real samples, the boundary must be:
- `...<|im_end|>\n<|endoftext|>\n<|im_start|>...`
- In other words, each real sample contributes one learned `EOD`, and if another real sample follows there is one extra separator newline after that `EOD`.
- Tail padding in the final packed chunk remains repeated `<|endoftext|>` with loss mask `0`.

Masking rules for the rewrite
- Only the final assistant block of each source sample is trainable.
- The assistant role prefix `<|im_start|>Assistant: ` remains masked.
- The trainable span must include:
- normalized final-assistant think block text,
- final assistant visible content,
- final assistant `tool_calls`,
- the final assistant closing `<|im_end|>`,
- and the sample-final `<|endoftext|>`.
- The masked span must include:
- system text,
- tool schema,
- user text,
- tool responses,
- earlier assistant outputs,
- packing separator newline,
- and padding `<|endoftext|>` tokens.

Think normalization rules to implement
- The final assistant in the processed training text should always contain think tags.
- If the final assistant content already contains `</think>`:
- prefix render for mask boundary uses `add_generation_prompt=True`, `enable_thinking=False`, `no_add_thinking=True`.
- full render uses the original final assistant content unchanged with `add_generation_prompt=False`, `enable_thinking=False`, `no_add_thinking=True`.
- If the final assistant content does not contain `</think>`:
- prefix render for mask boundary uses `add_generation_prompt=True`, `enable_thinking=False`, `no_add_thinking=False`, so the generated prefix ends with ` <think>\n\n</think>\n\n`.
- full render manually prepends `<think>\n\n</think>\n\n` to `messages[-1]["content"]`, then uses `add_generation_prompt=False`, `enable_thinking=False`, `no_add_thinking=False`.
- Malformed edge cases such as content containing only `</think>` must be covered by tests and handled consistently with the chosen template semantics.

Implementation outline
- Stop treating Python-built segments as the source of truth for SFT text formatting.
- Build a real Jinja rendering path with the same `tojson` behavior used by the sample conversion script.
- Use render-twice mask derivation:
- first render excludes the final assistant and gives the masked prefix length,
- second render includes the full sample and gives the full text,
- the trainable span starts immediately after the assistant role prefix in the second render and ends at the end of the rendered sample text.
- Tokenize the final rendered sample text once, then derive token-level loss mask from the byte-span boundary.
- Keep the existing `.bin/.idx` plus `.mask.bin/.mask.idx` storage format.
- Update packing logic so real samples are joined by learned `EOD` plus one masked separator newline, while tail padding still uses masked `EOD` only.
